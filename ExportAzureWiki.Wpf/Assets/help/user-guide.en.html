User Manual

This manual explains how to perform each operation in the app: initial setup, registering wikis, users, permissions, providers, AI and export. Use the side menu to jump to a topic.

1. First Access (Onboarding)

When it appears

On the first run on a machine with no initial configuration. The wizard has up to 5 steps.

Step 1 - Language

Pick Portugues or English. The whole interface, including the rest of the wizard, follows the chosen language.

Step 2 - Install mode

  • New installation: creates the database from scratch (tables + default providers) and an administrator user.
  • Existing database: points to a database already created by another machine/team. In this mode the admin step is skipped.

Step 3 - Database

Select the database type. On selection, the default port is filled automatically and the default database name is AWikiExporterDB.

TypeFieldsDefault portNote
SQLiteFile only (.db)-Local, serverless. Ideal for individual/test use.
SQL ServerServer, database, user, password1433Supports Windows authentication.

Advanced options (server databases)

  • Trust server certificate: enable when the server uses an internal/self-signed TLS certificate ("certificate chain not trusted" error).
  • Windows authentication SQL Server only: uses the current Windows user; the user/password fields are hidden.

Step 4 - Administrator

  1. Enter username, e-mail (optional) and password.
  2. The password policy checklist is ticked live as you type (uppercase, lowercase, number, symbol, minimum length).
  3. Confirm the password and continue.

Step 5 - Completion

Click Start Application. The login screen opens right after (no need to reopen the app).

If your team already has a connection token (section 10), "existing database" + token reduces manual database setup errors.

2. Login

Local login

  1. Fill Username and Password.
  2. Click Sign in.

Azure login

  1. Click Sign in with Azure.
  2. Complete authentication at the provider (browser/corporate identity).
Even with Azure, the user must exist (or be imported) in the local registry to gain access.
After several wrong-password attempts the account may enter a temporary lockout. Wait for the indicated time or ask an administrator to unlock.

After login

The app checks whether any wiki is configured. If none and you are an admin, you are routed to Wiki Management to register the first one.

3. Workspace (daily use)

Load wiki pages

  1. Select the wiki in the wiki combo.
  2. In the tree, check the desired pages/folders.
  3. Click Load Pages.
  4. Navigate with Previous and Next.

Important options

  • Refresh Cache: reloads content from the source (drops the local cache).
  • Dark Mode: changes display only.
  • Code Theme: changes the code block style.
  • Open .md File: loads a local markdown file from disk.
At the top of the workspace you see the current page path and the last rendered update date.

4. Register Wiki (Wiki Management)

Create a new wiki

  1. Open Wiki Management.
  2. Click New.
  3. Fill Name, choose the Platform and the Authentication type.
  4. Enter the Organization URL and the platform fields (see 4.1).
  5. Click Test Connection to validate.
  6. Click Pages and select start points (or leave empty for everything - see 4.3).
  7. Click Save.

Edit / Delete

  • Edit: select the wiki in the grid, click Edit, change and Save.
  • Delete: select the wiki, click Delete and confirm.
Deleting a wiki clears its linked permissions and cache automatically.

GitHub token scope

  • Fine-grained PAT: access to the repo with Contents: Read-only.
  • Classic PAT: repo scope (or public_repo if the repository is public).
  • In Wiki mode, the token is used to clone ...wiki.git.
Tokens and passwords are masked on screen (with an "eye" reveal button) and stored encrypted.

4.3 Start Points

Start points limit which folders/files the wiki will bring.

  1. In the wiki form, click Pages.
  2. The app lists the available page tree.
  3. Check the desired folders/pages and confirm.
  • No start point = the wiki brings everything within scope (on GitHub, the whole repo when Docs Path is also empty).
  • Selecting a folder brings every page inside it.
Docs Path and Start Points work together: Docs Path narrows the base folder; Start Points narrow further within it.

5. Register Users and Groups

Local user

  1. Open Users and Groups.
  2. Click New User and pick type Local.
  3. Fill username, name, e-mail (optional), password and confirmation.
  4. Click Save.

External user

  1. New user and select an external type (Azure/AD/GitHub).
  2. Select the matching provider.
  3. Search active users, pick one and save.

Group

  1. Click New Group, enter name and description.
  2. Save and then add members.

6. Configure Permissions

System permission

  1. Open Permissions and select a user or group.
  2. Check: Administrator, Manage Wikis, Manage Users, Manage Permissions.
  3. Click Save.

Per-wiki permission

  1. With the policy selected, click Add rule.
  2. Choose the wiki and the allowed start points.
  3. Check: view, comment, Word, PDF, letterhead.
  4. Save the rule and then the policy.
If a user cannot see a wiki, check the CanView rule and the start points first.

7. Configure Providers

Authentication providers

  1. Open Providers and create/edit an OAuth or Azure AD provider.
  2. Fill ClientId, Secret, Redirect and Tenant (when applicable).
  3. Enable the provider and save.

Default OAuth providers (Azure AD, GitHub, Google, Microsoft) come pre-registered, disabled, awaiting credentials.

AI providers

  1. Create a new AI provider.
  2. Fill endpoint, key, model and version.
  3. Adjust timeout, temperature and max tokens.
  4. Save and, if needed, mark as default.
The AI API key is stored encrypted at rest.

8. Use AI on Content

  1. In the Workspace, load one or more pages.
  2. Choose the scope: current page or all loaded pages.
  3. Click Summary, Index or Quiz.
  4. In the result modal, review in Preview.
  5. Click Add to preview to include it as an extra page.
If the AI button is disabled, review the AI provider (enabled + key + model).

9. Export Word/PDF

Export Word

  1. Define the export scope.
  2. Optional: include AI pages and apply Word fine-tuning.
  3. Click Export to Word and pick the file location.

Export PDF

  1. Define the scope (same flow).
  2. Click Export to PDF.

10. Generate Connection Token

The connection token packages database access data to configure another machine without retyping everything.

  1. As an admin user, open the Connection Token menu.
  2. Set the validity.
  3. Click generate and choose where to save the file.
  4. Use that file in the onboarding ("existing database" mode) of the new machine.
The token file contains sensitive connection data. Share it only through secure channels.

11. Manage Data

Screen to selectively export, import and clear data, plus reset the local installation.

Export / Import admin only

  1. Open Manage Data.
  2. Check what you want: Wikis, AI providers and/or OAuth providers.
  3. Click Export to save a file, or Import to load from a file.

Clear data

Select the categories and confirm to remove them from the database. Useful to redo a setup from scratch without reinstalling.

Local reset

Removes this machine's local configuration (registry + local folders) and closes the app. Use when you need to fully uninstall/clean the app from this machine.

Clear and reset are irreversible. Export first if you want a backup.

12. Recommended Operating Routine

  1. Update/validate providers and permissions (when there are changes).
  2. Load the pages in the workspace.
  3. Apply AI, if needed.
  4. Review the preview.
  5. Export Word/PDF.

14. Glossary and FAQ

Glossary

  • Start point: starting folder/page from which the wiki is listed.
  • Docs Path: base folder in the GitHub repository; empty = whole repository.
  • Source mode: on GitHub, chooses between repository files (Repository) or the Wiki tab.
  • PAT: Personal Access Token, credential to access the GitHub/Azure API.
  • Provider: external authentication (OAuth/Azure) or AI provider.
  • Permission policy: set of access rules for a user/group.
  • Connection token: file that carries the database configuration to another machine.

FAQ

Can I use the app without a database server? Yes, choose SQLite in setup.

Do I need a token for a public repository? In Repository mode it works with a minimal token; without a token there is a request rate limit.

How do I get everything from the repository? Empty Docs Path + no start points.

Where are the logs? In %LocalAppData%\ExportAzureWiki\Logs.
