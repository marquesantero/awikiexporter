Manual do Usuario

Este manual ensina como executar cada tarefa na aplicacao: instalacao inicial, cadastro de wikis, usuarios, permissoes, providers, IA e exportacao. Use o menu lateral para ir direto ao topico.

1. Primeiro Acesso (Onboarding)

Quando aparece

Na primeira execucao da aplicacao em uma maquina sem configuracao inicial. O assistente tem ate 5 etapas.

Etapa 1 - Idioma

Escolha Portugues ou English. Toda a interface, inclusive o restante do assistente, passa a respeitar o idioma escolhido.

Etapa 2 - Modo de instalacao

  • Nova instalacao: cria o banco do zero (tabelas + provedores padrao) e um usuario administrador.
  • Base existente: aponta para um banco ja criado por outra maquina/equipe. Nesse modo a etapa de criar admin e pulada.

Etapa 3 - Banco de dados

Selecione o tipo de banco. Ao escolher, a porta padrao e preenchida automaticamente e o nome padrao do banco e AWikiExporterDB.

TipoCamposPorta padraoObservacao
SQLiteApenas arquivo (.db)-Local, sem servidor. Ideal para uso individual/teste.
SQL ServerServidor, banco, usuario, senha1433Suporta autenticacao Windows.
PostgreSQLServidor, banco, usuario, senha5432-
MySQLServidor, banco, usuario, senha3306-

Opcoes avancadas (bancos de servidor)

  • Confiar no certificado do servidor: marque quando o servidor usa um certificado TLS interno/auto-assinado (erro de "cadeia de certificados nao confiavel").
  • Autenticacao Windows somente SQL Server: usa o usuario do Windows atual; os campos usuario/senha ficam ocultos.

Etapa 4 - Administrador

  1. Informe usuario, e-mail (opcional) e senha.
  2. A lista de politicas de senha e marcada em tempo real conforme voce digita (maiuscula, minuscula, numero, simbolo, tamanho minimo).
  3. Confirme a senha e avance.

Etapa 5 - Conclusao

Clique em Iniciar Aplicacao. A tela de login abre em seguida (sem precisar reabrir o app).

Se sua equipe ja tem um token de conexao (secao 10), o modo "base existente" + token reduz erros de configuracao manual do banco.

2. Login

Login local

  1. Preencha Usuario e Senha.
  2. Clique em Entrar.

Login Azure

  1. Clique em Entrar com Azure.
  2. Conclua a autenticacao no provedor (navegador/identidade corporativa).
Mesmo no Azure, o usuario precisa existir (ou ter sido importado) no cadastro local para obter acesso.
Apos varias tentativas com senha errada a conta pode entrar em bloqueio temporario (lockout). Aguarde o tempo indicado ou peca a um administrador para liberar.

Apos o login

O app verifica se existe alguma wiki configurada. Se nao houver e voce for admin, voce e direcionado para o Wiki Management para cadastrar a primeira.

3. Workspace (uso diario)

Carregar paginas da wiki

  1. Selecione a wiki no combo de wikis.
  2. Na arvore, marque as paginas/pastas desejadas.
  3. Clique em Load Pages (Carregar Paginas).
  4. Navegue com Previous e Next.

Opcoes importantes

  • Refresh Cache: recarrega o conteudo a partir da origem (descarta o cache local).
  • Dark Mode: altera apenas a visualizacao.
  • Code Theme: muda o estilo dos blocos de codigo.
  • Open .md File: carrega um markdown local do seu disco.
No topo do workspace voce ve o caminho da pagina atual e a data da ultima atualizacao renderizada.

4. Cadastrar Wiki (Wiki Management)

Criar nova wiki

  1. Acesse Wiki Management.
  2. Clique em Novo.
  3. Preencha Nome, escolha a Plataforma e o Tipo de Autenticacao.
  4. Informe a Organization URL e os campos da plataforma (veja 4.1).
  5. Clique em Test Connection para validar.
  6. Clique em Pages e selecione os start points (ou deixe vazio para tudo - veja 4.3).
  7. Clique em Salvar.

Editar / Excluir

  • Editar: selecione a wiki no grid, clique em Editar, altere e Salvar.
  • Excluir: selecione a wiki, clique em Excluir e confirme.
Ao excluir uma wiki, as permissoes e o cache vinculados sao limpos pelo sistema.

4.2 Tipos de Autenticacao

TipoCamposQuando usar
Personal Access TokenToken (GitHub/Azure) ou App Password (Bitbucket)Caso mais comum. Recomendado.
Basic AuthUsuario + SenhaServidores que exigem usuario/senha.
API KeyAPI KeyIntegracoes baseadas em chave.
OAuthClient ID, Secret, Tenant, Scopes, Redirect URIFluxo corporativo via provider OAuth.

Escopo do token GitHub

  • Fine-grained PAT: acesso ao repo com permissao Contents: Read-only.
  • Classic PAT: escopo repo (ou public_repo se o repositorio for publico).
  • Em modo Wiki, o token e usado para clonar ...wiki.git.
Tokens e senhas sao mascarados na tela (com botao de "olho" para revelar) e guardados criptografados.

4.3 Start Points (pontos de partida)

Start points limitam quais pastas/arquivos a wiki vai trazer.

  1. No cadastro da wiki, clique em Pages.
  2. O app lista a arvore de paginas disponiveis.
  3. Marque as pastas/paginas desejadas e confirme.
  • Sem nenhum start point = a wiki traz tudo dentro do escopo (no GitHub, o repo inteiro quando o Docs Path tambem esta vazio).
  • Selecionar uma pasta traz todas as paginas dentro dela.
Docs Path e Start Points trabalham juntos: Docs Path restringe a pasta-base; Start Points restringe ainda mais dentro dela.

5. Cadastrar Usuarios e Grupos

Usuario local

  1. Abra Users and Groups.
  2. Clique em Novo Usuario e escolha o tipo Local.
  3. Preencha usuario, nome, e-mail (opcional), senha e confirmacao.
  4. Clique em Salvar.

Usuario externo

  1. Novo usuario e selecione tipo externo (Azure/AD/GitHub).
  2. Selecione o provider correspondente.
  3. Busque usuarios ativos, escolha um e salve.

Grupo

  1. Clique em Novo Grupo, informe nome e descricao.
  2. Salve e depois adicione membros.

6. Definir Permissoes

Permissao de sistema

  1. Abra Permissions e selecione usuario ou grupo.
  2. Marque: Administrador, Gerenciar Wikis, Gerenciar Usuarios, Gerenciar Permissoes.
  3. Clique em Salvar.

Permissao por wiki

  1. Com a politica selecionada, clique Adicionar regra.
  2. Escolha a wiki e os start points permitidos.
  3. Marque: visualizar, comentar, Word, PDF, papel timbrado.
  4. Salve a regra e depois a politica.
Se o usuario nao enxerga uma wiki, verifique primeiro a regra CanView e os start points.

7. Configurar Providers

Providers de autenticacao

  1. Acesse Providers e crie/edite um provider OAuth ou Azure AD.
  2. Preencha ClientId, Secret, Redirect e Tenant (quando aplicavel).
  3. Ative o provider e salve.

Os provedores OAuth padrao (Azure AD, GitHub, Google, Microsoft) ja vem pre-cadastrados, desabilitados, aguardando credenciais.

Providers de IA

  1. Crie um novo provider de IA.
  2. Preencha endpoint, chave, modelo e versao.
  3. Ajuste timeout, temperature e max tokens.
  4. Salve e, se necessario, marque como padrao.
A chave de API de IA e guardada criptografada em repouso.

8. Usar IA no Conteudo

  1. No Workspace, carregue uma ou mais paginas.
  2. Escolha o escopo: pagina atual ou todas as paginas carregadas.
  3. Clique em Summary, Index ou Quiz.
  4. No modal de resultado, revise em Preview.
  5. Clique em Add to preview para incluir como pagina extra.
Se o botao de IA estiver desabilitado, revise o provider de IA (habilitado + chave + modelo).

9. Exportar Word/PDF

Exportar Word

  1. Defina o escopo de exportacao.
  2. Opcional: incluir paginas de IA e aplicar o ajuste fino do Word.
  3. Clique em Export to Word e escolha o local do arquivo.

Exportar PDF

  1. Defina o escopo (mesmo fluxo).
  2. Clique em Export to PDF.

10. Gerar Token de Conexao

O token de conexao empacota os dados de acesso ao banco para configurar outra maquina sem digitar tudo de novo.

  1. Com usuario admin, abra o menu Connection Token.
  2. Defina a validade.
  3. Clique em gerar e escolha onde salvar o arquivo.
  4. Use esse arquivo no onboarding (modo "base existente") da nova maquina.
O arquivo de token contem dados sensiveis de conexao. Compartilhe apenas por canais seguros.

11. Gerenciar Dados

Tela para exportar, importar e limpar dados de forma seletiva, alem de resetar a instalacao local.

Exportar / Importar somente admin

  1. Abra Gerenciar Dados.
  2. Marque o que deseja: Wikis, Provedores de IA e/ou Provedores OAuth.
  3. Clique em Exportar para salvar um arquivo, ou Importar para carregar de um arquivo.

Limpar dados

Selecione as categorias e confirme para remove-las do banco. Util para refazer um cadastro do zero sem reinstalar.

Reset local

Remove a configuracao local desta maquina (registro + pastas locais) e fecha o app. Use quando precisar desinstalar/limpar completamente o app desta maquina.

A limpeza e o reset sao irreversiveis. Exporte antes se quiser um backup.

12. Rotina Recomendada de Operacao

  1. Atualize/valide providers e permissoes (quando houver mudancas).
  2. Carregue as paginas no workspace.
  3. Aplique IA, se necessario.
  4. Revise o preview.
  5. Exporte Word/PDF.

14. Glossario e FAQ

Glossario

  • Start point: ponto de partida (pasta/pagina) a partir do qual a wiki e listada.
  • Docs Path: pasta-base no repositorio GitHub; vazio = repositorio inteiro.
  • Source mode: no GitHub, escolhe entre arquivos do repositorio (Repository) ou a aba Wiki.
  • PAT: Personal Access Token, credencial de acesso a API do GitHub/Azure.
  • Provider: provedor externo de autenticacao (OAuth/Azure) ou de IA.
  • Politica de permissao: conjunto de regras de acesso de um usuario/grupo.
  • Token de conexao: arquivo que transporta a configuracao do banco para outra maquina.

FAQ

Posso usar o app sem servidor de banco? Sim, escolha SQLite no setup.

Preciso de token para repositorio publico? Em modo Repository funciona com token minimo; sem token ha limite de requisicoes.

Como pego tudo do repositorio? Docs Path vazio + nenhum start point.

Onde ficam os logs? Em %LocalAppData%\ExportAzureWiki\Logs.
